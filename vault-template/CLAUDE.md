# Knowledge vault — maintenance contract

This is an **LLM-maintained knowledge wiki** (Karpathy's llm-wiki pattern). Read
this before touching anything. Your job is to keep the wiki accurate and
cross-linked; the human curates sources and asks questions.

## Three layers

| Layer | Path | Who owns it | Rule |
|-------|------|-------------|------|
| **Raw sources** | `raw/` | the hourly loop | **Immutable.** Append only, never edit or delete. One subdir per source: `slack/ claude/ outlook/ confluence/ inbox/`. Dated files `YYYY-MM-DD.md`. |
| **Wiki** | `wiki/` | **you** (the LLM) | Curated, synthesized pages: `concepts/ people/ projects/ tech/ clippings/ areas/`. Create, merge, and cross-link these. |
| **Meta** | `meta/` | tooling | Templates, promotion drafts, loop bookkeeping. Not knowledge. |

Two navigation files at the root are **generated — never hand-edit them**:
- `index.md` — catalog of every wiki page, regenerated by `reindex.py`.
- `log.md` — append-only chronological event stream (ingests, promotions, lints).

`archive/` holds done/dead material.

## Frontmatter (every wiki note)

```yaml
---
type: reference | concept | person | project | moc | note
title: Human Title
description: one line — this is what shows in the catalog and drives retrieval
tags: [kebab-case, ...]
timestamp: 2026-07-02T00:00:00Z
---
```

`title` + `description` are high-signal: they populate `index.md` and are what
qmd embeds. Write them well.

## Links

- Cross-reference with `[[wikilinks]]` (Obsidian resolves by basename, so they
  survive file moves). Use markdown `[text](relative/path.md)` only for
  same-directory links.
- Link liberally. A page's value is its connections. When you add a fact to one
  page, link the entities and concepts it touches.

## Operations

**Ingest** (a new raw file appeared): read it, extract durable facts, and
update/create the relevant `wiki/` pages — then link them. A single source may
touch several wiki pages. The hourly loop does the *capture*; promotion into the
wiki is `promote.sh` (drafts) → human review → `promote-apply.py`.

**Query**: retrieve with **qmd** (hybrid BM25 + vector + rerank), never grep:
```
qmd query "your question" --json        # ranked hits across raw + wiki
qmd query "..." -c wiki                  # restrict to the curated layer
qmd get wiki/concepts/foo.md             # read a specific page
```
A good answer worth keeping should be **filed back** as a new wiki page — that's
how the wiki compounds instead of evaporating into chat.

**Lint** (periodic): `reindex.py` regenerates the catalog and flags dead links;
`plasmie-improve.py` archives resolved drafts and logs changes. Also watch for
contradictions, stale claims, and concepts with no inbound links.

## Boundaries

- Never edit or delete anything under `raw/` — it's the audit trail of what
  actually happened.
- Work content only (laptop): no personal finances, family, or health.
- Don't hand-edit `index.md` / `log.md`; change the generators instead.
